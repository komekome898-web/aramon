# モンスター追加ツール(tools/)

**新しいモンスターは手作業で表に書かず、ツールで追加する。** 詳細は`tools/README.md`。

- **iPhone完結版(主役)**: `tools/studio_web.html` = GitHub Pagesに置いた静的HTML1枚(`.../aramon/tools/studio_web.html`)。**依存ゼロ・端末内で完結**し、動画→8コマ・静止画整形・9表への登録・**GitHubへの1コミット送信**まで行う。認証はfine-grained PAT(Contents: Read and write、対象リポジトリのみ)をlocalStorage(`aramon_gh_token`)に保存。**コミット先はmain直接**で`sw.js`の`CACHE_NAME`も自動で+1する。取り消しボタンは`/*@key*/`の行を消してコミットし直す(CLIの`--revert`相当)。
- **GUI(Mac/PC)**: `python3 tools/monster_studio.py` → `http://127.0.0.1:8777`。背景の抜き方を切り替えながら8コマをその場でプレビューし、問題のあるコマを赤枠で理由付きに出す。`--lan`で同じWi-FiのiPhoneから画面だけ開ける。
- **CLI**: `python3 tools/monster_add.py <key>`(`--dry-run` / `--revert` / `--only sprites|portraits|code|check`)。仕様は`monsters/specs/<key>.json`。
- **検証**: `python3 tools/check_monsters.py`。`ELEMENTS`の全モンスターについて9表と画像の有無を機械的に見る。**追加作業の最後に必ず通す。**
- **表への挿入位置は各表末尾の`// <<AUTO:表名>>`の行。この行を消さない。** 追記した行には`/*@key*/`の目印が入り、`--revert`はこれを見て消す。
- 技はテンプレートを選ぶだけでコードを書かずに済む。tier1/2は絵文字(`REAL_ICON_FX`から自動列挙)、tier3は`fan`/`wave`/`crystal`/`beam`/`river`/`beams3`/`thunder`/`psychic`/`orb`/`tornado`/`sword`/`shell`/`crescent`/`spear`から選ぶ。
- **背景除去は`tools/build_walk.py`をそのまま呼んでいる**(モンスターごとに積み上げたモードの資産を捨てない)。`build_walk.py`は`import`しても`JOBS`が走らないようにしてあり、`build_frames()`が8コマを返し`process()`が保存する。
- 素材は`assets/<key>/`(gitに入れない)。CLI・Mac版GUIは`sw.js`を触らないので**コミット前に`CACHE_NAME`を上げる**(iPhone版だけ自動)。

## studio_web.html の要点

- **Python版と同じ行を出すことが前提。** `renderRows`/`buildMoves`/`jsMove`は`monster_code.py`/`monster_spec.py`の1:1移植なので、**片方を直したらもう片方も直す**(出力一致はnodeで文字列比較して確認できる)。移植していないのは`grass`(GrabCut)と256色量子化だけ(難しい背景はMac版へ回す)。
- **歩行は動画が無くても作れる**(iPhone版のみ)。**2枚以上の画像をそのままコマとして並べる**。**1枚の絵から動かす道は2026-09-02に削除した**(発注者決定。ルールで作った動きは「板が少し縮む」ようにしか見えず歩きにならない)。1枚しか無ければAIで動画にしてから動画経路へ回す。
- **8コマの下にゲームと同じ速さ(`WALK_FRAME_DUR`=0.11秒)のアニメーションを出す。** この値はdata.jsと二重に持っているので変えたら両方直す。
- **SSRスキンの登録もできる**(iPhone版のみ)。入れるのは`SSR_SKINS`/`SSR_SKIN_AURA`/`SSR_SKIN_TIER3`と`WALK_ANIM`の素体の中の4か所。**`WALK_ANIM`だけは表の末尾ではなく素体ブロックの中に挿す**ので`applySsrWalk()`が専用に処理する(`reg.ssr`は**配列**で1素体に何体でも持てる。同じ`skinId`が既にあれば`exists`を返し、素材だけ差し替える)。素体一覧はツールに書かず`data.js`の`ELEMENTS`から読む。
- **「既存の素材を差し替える」(`regKind='assets'`)は登録行を触らず画像だけ入れ替える。** 素体とSSRスキンを1つの一覧に並べ、用意したものだけ送る(歩行だけ・静止画だけも可)。**歩行コマ未登録のSSRは、画像の送信と同時に`WALK_ANIM`へも登録する** — これが無いと画像を送っても静止画のままになる(メタルグレイモンで実際に起きた。当時は「1素体に1つ」の制限で歩行16枚が黙って落とされていた)。差し替えは見た目だけなので`UPDATE_HISTORY`には足さない。
- **「覚醒スキンを作る」(`regKind='awaken'`)は元のSSRスキンから覚醒後の姿を作る。** 画像名は元のidから機械的に決める(`guts_ssr` → `guts_ssr_awake` / `guts_player_ssr_awake` / `guts_ssr_awake_walk_f1..8・b1..8`)ので入れ先を間違えない。**元にできるのは`awakenOf`が付いていないSSRだけ**(覚醒後をさらに覚醒させない)。
  - **絵の用意はSSRスキンの追加とまったく同じ手順に一本化してある**(`aw_mode='draw'`)。覚醒だけの別経路は持たない — 下の「歩行モーション」で動画か画像から16コマを作り、「静止画」でアイコンと試合用を作る。歩行に使う画像の入口は`imgF`/`imgB`**1か所だけ**で、背面が無ければ正面で代用する規則(`imageFilesFor`)も共通。
    - **画像生成をツールに組み込むのは試して取りやめた**(2026-08-10・発注者判断)。AI Horde / OpenAI / Google Gemini をブラウザから直接呼べるところまで作って実機で確認したが、**出来上がりが手作業の品質に届かなかった**。関わる項目はすべて削除済み。同じ方向を再提案しないこと。
      - このとき分かって残しておく価値のあること: **CORSは推測せず実測する。** この環境からは多くのホストが遮断されているが、**リポジトリのGitHub Actionsランナーは外に出られる**ので、そこから`curl -X OPTIONS`で確かめられる(`.github/workflows/`に調べもの用のワークフローを置き、`main`以外のブランチにだけ持つ)。掲示板の記述を鵜呑みにして「OpenAIはブラウザから叩けない」と誤って伝えた反省から。
  - **横に広い絵で左右が欠けないよう、倍率は2か所で同じ規則にしてある**(`fitScale()`)。`makePortrait`/`composeStrip`のどちらも高さで倍率を決めたあと幅で抑える(3か所目だった`synthWalkFrames`はA5で削除)。幅がはみ出さない絵では倍率が変わらないので既存の出力は変わらない。
  - **元の絵に光と素材を重ねる(`aw_mode='fx'`)**: 絵を用意しないで覚醒感だけ足す道。元スキンの18枚を`getRepoImage()`で取り、`awakenComposeOne()`で全部に同じ加工を掛ける。中心は**アルファから作るリムライト+外側グロー**(`awakenRimCanvas()`)で、どんな絵でも破綻しない。**重ねる素材は`awakenBodyBox()`で取った「そのコマの体の枠」に合わせて置く** — キャンバス中央に固定すると歩行コマで体から取り残されて貼り付いて見える(最初の実装がそれだった)。
  - 送信先は`SSR_SKINS`(**`awakenOf`付き**)/`SSR_SKIN_AURA`/`SSR_SKIN_TIER3`/`WALK_ANIM`の4か所で、**新しい表は作らない**。`awakenOf`が付いた行はガチャにもカタログにも出ない(`gachaSsrSkinIds()`/`raidGachaSsrSkinIds()`が除外する)。覚醒の条件文(転生◯回・全ステータス◯以上)は`UPDATE_HISTORY`に書くが、**数字は`data.js`の`AWAKEN_REBIRTH_REQ`/`AWAKEN_STAT_MIN`を読んで書く**(ツール側に写すと本体を変えたときにずれる)。
  - **できないこと**: 別ポーズで描かれた覚醒の絵から「鎧のパーツだけ」を既存の絵へ自動で貼ることはできない(体の線が違うと必ず破綻する)。絵を渡すなら18枚を作り直す側、既存の絵を活かすなら光と素材を重ねる側、と使い分ける。
- **色は3つ(明るい色/暗い色/差し色)ともパレットから選べる。** 入れる場所を選んでから色をタップする方式で、`<input type="color">`と16進の入力欄は双方向に同期する。
- **状態変化の選択肢は`data.js`の`STATE_CHANGES`をその場で読んで作る**(`parseStateChanges`)。`1/1.5`のような書き方も読めるように、数字と四則だけを通す`numExpr()`で評価している。**条件`SC_TRIGGERS`と効果`SC_EFFECTS`の一覧だけはツール側にも持っている**(data.jsの表の書式そのもの)。増やしたら両方直す。

## SSRスキン専用メディア(「SSRスキン専用」の登録)

- **行き先は`data.js`の`SKIN_MEDIA`1か所だけ。** 昇格演出(無音動画+音声)・試合中BGM3曲・専用SE4種・宣伝画像をここへ書けば、audio.js / combat.js / ui.js が表を読んで動く。**ゲーム側のコードは1行も足さない。**
- **既存の設定は必ず「取得したdata.js」から読み直して土台にする**(`parseSkinMedia`)。添付した項目だけ差し替わり、触っていない項目は今のパスがそのまま残る。
- **入れ替えは「消してから足す」。** `/*@id*/`の目印は他の表(`SSR_SKINS`など)にも付いているので、`removeSkinMediaEntry()`は**`SKIN_MEDIA`ブロックの中だけ**を消す(`revertRows`をそのまま使うとスキン登録ごと消える)。
- **音声・無音動画はMediaRecorderで実時間に録り直す**(`captureFromVideo`)。音は`MediaElementSource → MediaStreamDestination`へ流すのでスピーカーからは鳴らず、映像は`video.captureStream()`の映像トラックだけを録るので音無しになる(`captureStream`が無い端末はcanvasへ描き写す)。**昇格演出は音と映像を1回の再生で同時に録る**(2回再生させない)。**音声ファイルを直接添付したときは録り直さずそのまま送る。**
- 出来上がりの拡張子は端末が対応する形式(iPhoneなら`.m4a`/`.mp4`)。**`sw.js`の`MEDIA_RE`に`m4a|aac`を入れてある**(入れないとSWの素材キャッシュに載らない)。
- **今入っている素材のプレビューは、Pages上の相対パス(`../audio/…`)をそのまま再生する。** ツールも本番も同じオリジンなのでCORSも認証も要らない。昇格演出だけは**本番と同じ「共通(ssr_promote)→ 専用」の2本**を並べて出す(`promotePreviewHtml`)。専用だけ見ていると実際の見え方と食い違うため。
- **昇格演出を足すと、管理者画面「機能」タブの確認ボタンも自動で増える。** ui.jsの`renderAdminPromoteCheckBtns()`が`SKIN_MEDIA`から`promote.video`を持つスキンを列挙して作るので、**index.htmlにもui.jsにもボタンを書き足さない。**
- ピックアップは表ではなく1行の定数の書き換え(`GACHA_PICKUP_SSR` / `RAID_GACHA_PICKUP`)。**タイトルの「(◯◯ピックアップ)」もガチャ画面・ロビーの記念ポップアップの画像も、この定数と`SKIN_MEDIA.promoImg`から作られる**ので、ツールが直すのは定数と表だけでよい。
- 書き込みは**Git Data API**(blobs→tree→commit→PATCH ref)。ファイル単位のPUTだと18コミットになる。読み込みは**Contents API**(Pages経由だとSWのキャッシュで古い内容を掴む)。

## 削除した機能: 1枚絵からの歩行合成(パーツ分割)

- **2026-09-02に削除した**(発注者決定)。`detectParts`/`protrusionsAt`/`chamferDist`/`analyzeRigFromCut`/
  `rigBase`/`rigThumb`/`synthWalkFrames`/`partMotion`/`MOT`/`PART_*`/`RIG_*`と、そのUI(動きの種類・
  揺らし方・動きの強さ・踏み出し量・パーツ一覧)がすべて無い。
- **理由**: 1枚の静止画から歩行周期をルールで作るのは無理筋だった。パーツが取れても動きは
  「付け根を軸に前後へ振る」だけで、膝も肘も曲がらず布も揺れないので「板が少し縮む」ようにしか見えない。
  ローブ・マントの絵ではそもそもパーツが0個になって全体揺れへ落ちる。
- **同じ方向を再提案しないこと。** 歩きは**動画の側**(AIで動画化 → 動画経路)でしか作れない。
  1枚しか絵が無いときの案内は「AIで動画にしてから『動画から作る』へ」。

## 動画まわりの落とし穴

- **周期は「下半身の帯 → ドリフト除去 → 山があれば山 / 無ければ谷×2」で求める**(`detectPeriod` / `build_walk.py`の`detect_period`。**同じ手順・同じ定数なので片方を直したらもう片方も直す**)。全体の自己相関をそのまま使うと寄り・ズーム・明るさの変化に埋もれて右肩下がりの曲線にしかならず、**探索範囲の下限がそのまま返って1歩ぶんに足りない長さで切られる**(片足しか上がらない。2026-08-01に発生)。要点は4つ: ①脚が写る下の帯(`PERIOD_BAND`)だけ見る ②移動平均を引く ③**自己相関は`n`で割る**(`n-lag`で割ると後ろのlagほど値が大きくなり周期の2倍・4倍が最大になる) ④`PERIOD_PEAK_MIN`以上の山があればそれ、無ければ谷(`PERIOD_DIP_MAX`以下)の2倍、どちらも無ければ従来の山の探索。
- **動画からは候補16コマ(`CAND_N`)を出し、その中から8コマ選ばせる。** 「切り出す長さ」(`#spanMul`)は周期の倍率で、半分で拾ってしまったときに2倍にすると1周期ぶん入る。
- **動画は「一瞬だけ再生してから」canvasへ描く。** iOSはメタデータだけ読めた動画を`drawImage`しても何も描かれず、その空の絵に背景透過をかけると**真っ黒な8コマ**ができる(2026-08-01に発生)。`loadVideo`は`readyState>=2`まで待ち(動画要素は画面外に置いてDOMへ入れる。iOSは画面に無い動画を再生できないことがある)、`primeVideo()`が無音・インラインで一瞬再生してデコーダを起こし、`seekTo`は`afterSeekPaint()`でコマが描ける状態になるまで待つ。**この3つはセットで、1つ欠けると同じ症状に戻る。** 解析コマが一様(`gmax-gmin<3`)なら止め、被写体の枠がコマ全体(98%超)になったときも止める。
- **動画まわりの待ちにはすべて上限を付ける。** 1つでも返らないと「コマを作っています」のまま永久に固まる(2026-08-01に発生)。`loadVideo`は3秒で先へ進み12秒で必ずエラー、`primeVideo`は1.2秒、`seekTo`は0.6秒、`afterSeekPaint`は0.12秒。`canvasToBlobPng`/`blobToDataUrl`も失敗時にrejectする。**進捗は`walkStep()`で件数付きに出す。**
- **外周に枠線のある動画は「少し内側の輪」から背景を探す**(`BORDER_INSETS`)。外周1〜2pxが暗い枠線だと白い背景が画像の縁に触れず、`borderConnected`が背景を1つも見つけられない(2026-08-01に発生)。**内側で見つけたときは枠ぶんを`fg`から切り離してから`keepLargest`する。** 抜けなかったときは`cornerHint()`が**外周8点(四隅+辺の中央)**の色から試すべき抜き方を返す(色を決めるのは`cornerRgb`1か所)。
- **候補コマの時刻は秒で直接決める**(解析の目盛りに丸めない)。丸めると周期が短いときに同じコマが何組も候補に並ぶ。`ANALYZE_N`は多いほど遅く、48で0.75秒の周期まで見分けられる。

### コマの取り出しは**シークではなく再生**(2026-08-11)

- **`currentTime`で飛ばしてはいけない。** iOSは画面に出ていない`<video>`をシークしても表示コマが更新されないことがあり、**16コマ全部が同じ絵**になる(実機で発生)。**周期の倍率を変えても結果が変わらないのがこの症状の見分け方。**
- 正は`playThrough(v, from, to, onFrame)`。再生しながら`requestVideoFrameCallback`(無ければ`requestAnimationFrame`)で1コマずつ拾う。**解析用の1周と、候補16コマ用の1周で計2周**回す。
- **枠は前から順に「その時刻に達した最初のコマ」で埋める**(`slot`を1つずつ進める)。時刻の近さで選ぶ形だと同じコマが2枠に入る。この作りなら**16枠が必ず別々のコマになる**。
- **切り出す長さは動画のコマ間隔×16を下回らせない**(`frameDt`は実測の中央値)。下回ると物理的に同じ絵が並ぶ。
- **コマが本当に動いているかを必ず確かめる**(`grayDiff`が`MOVE_MIN_DIFF`未満**かつ**時間をおいた差も`MOVE_SPAN_MIN_DIFF`未満ならエラーで止める。下の「AI動画の受け入れ」を参照)。ここを見ていなかったため「同じ静止画が8枚」を作って気づけなかった。

### AI動画(Seedance)の受け入れ(2026-09-02)

- **元動画に歩行が無ければ、ツールでは歩かせられない。** あるるかん・疾風が「8コマほぼ同じ絵」になったのは、**元のSeedance動画に脚の交互が無く、布と髪が揺れるだけ**だったため(ローブで脚が隠れている)。**歩きは動画の側(プロンプト)でしか作れない。** 動画パネルの定型文(`SEED_PROMPT`・日本語+英語)がその条件を書いてある: その場で足踏み・脚がはっきり見える・カメラ固定・単色背景(緑)・5秒に2歩以上・キャラは中央に全身。
- **「コマが変わっていない」の判定は2つの見方で見る**(`MOVE_MIN_DIFF`=隣り合うコマ / `MOVE_SPAN_MIN_DIFF`=先頭から離れたコマ)。隣だけで見ていたため、**発注者のSeedance動画が通ったり弾かれたりしていた** —— この素材は隣接差が 1.1〜2.8 と `MOVE_MIN_DIFF`(1.2)の境目をまたぐ(時間をおいた差は 9.7 で安定。2026-09-02に実測)。**速い端末ほど1コマぶんの差が小さくなるので、iPhoneでこそ起きる。** 止まっている動画は**どちらも0**なので、2026-08-11の守りは効いたまま。
- **本当の核心は「異常を検知できていなかった」こと。** 昔は周期18を黙って採り「問題は見つかりませんでした」と報告していた。今は**周期の強さ(自己相関の山)を数字で出し、`PERIOD_PEAK_MIN`未満なら「歩行の周期が見つかりません」とはっきり言う**。さらに`inspectFrames`が**隣のコマとの差**を見て、`FRAME_SAME_DIFF`未満なら「前のコマとほぼ同じ絵」で赤くする(輪になるように最後→先頭も見る)。
- **「歩行の周期があるか」を決めるのは`periodFound(p)`(= `p.peak >= PERIOD_PEAK_MIN`)の1か所だけ。** 画面の言い方も、「自動」で第2手へ切り替えるかも、検査もここを読む。**`how`(peak / dip / none)は周期の“長さの求め方”であって歩行の有無ではない** —— `how !== 'none'`で判定していたころは、谷から求めた枝(`dip`)だと**強さ0.05でも「見つかりました」と言い、第2手にも切り替わらなかった**(ズームだけの動画で発生・2026-09-02)。回帰(c)に「ズームだけの入力(`how='dip'`・強さ0.05)を歩行ありと言わない」を入れてある。
- **周期の強さで「歩いている」と断定しない。** 画面は「周期らしさ 0.47(歩きと揺れは区別できません)」と出し、**並べた後の隣接差(最小・平均)と「8コマを目で確かめてください」を常に添える**。緑(`ok`)の断定は出さない。周期が弱いときは定型文(A6)への案内も出す。
- **自己相関は`bandAutocorr()`1か所で作る。** `detectPeriod`(周期だけ返す)も`periodDiag`(周期+強さ+どの枝を通ったか)もここを読む。**2か所で計算すると「診断は周期ありと言うのに切り出しは周期なしで動く」ことになる。** `detectPeriod`の返り値は今までと1つも変わらない(回帰(c)のゴールデンで固定)。
- **注意: `bandAutocorr`は「歩き」と「その場の揺れ」を区別できない。** 全身が上下に揺れるだけでも帯の自己相関に山が立つ(実物のSeedance動画で 0.468@18コマ)。数字が高い=歩いている、ではない。最後の拠り所は**並べた後の8コマの隣接差**。

- **背景色は外周8点(四隅+辺の中央)の中央値で自動判定する**(`cornerRgbs`→`cornerRgb`。中央値の式は`medianOf`1か所)。四隅だけだと角の透かし(PowerDirectorのロゴ)を拾う。タップは「自動が外れたときの上書き」で、`state.chromaAuto`が立っている間だけ自動が入り直す(素材を選び直すと`resetChromaAuto('w'|'p')`で自動へ戻る。**歩行と静止画で別々に戻す** —— まとめて戻していたころは静止画の素材を選ぶだけで歩行の拾った色が捨てられた)。`cornerHint`もこの色を読む(判定を2か所に持たない)。
- **動画を選んだら「背景の抜き方」の既定は`chroma`**(§3 B2。`applyWalkModeDefault()`1か所)。背景色は上の自動判定で決まるので**タップ0回**で抜ける。**人が`#mode`を選び直したあとは上書きしない**(印は`modeTouched`の1つだけ。`$('mode').onchange`は引数があるとき=人の操作のときだけ印を立てる)。
- **足元の影は`dropFootShadow()`1関数で落とす**(既定ON)。被写体のいちばん下の帯(`SHADOW_BAND`)で「暗い(その絵の明るさの中央値比)・彩度が低い・横に長い・**枠の中が詰まっている**(`SHADOW_FILL`)」かたまりだけ。**影を落としてから枠を取り直す** —— 影ごと枠に入れると足元合わせの基準が影の下端になって跳ねる。**「詰まっている」が無いと絵の下の細い線画を影と間違える** —— ゲームに入っている静止画で illumine(479画素・0.14%)・mocchi_ssr(2322画素・0.45%)を消していた(線画は枠の埋まりが3〜5%、落ち影は塊)。**「影が無い絵では1画素も変わらない」は合成画像の話で、実素材では成り立っていなかった。** いまは回帰が**`monsters/*.png`の静止画89枚で0画素**・**影が焼き込まれた歩行コマ(`illumine_walk_f1.png`)では落ちる**の両方を見る。

### 背景の抜き方(`segment()`)

- **背景かどうかは「背景色にどれだけ近いか」だけで決める**(`keyDistance()`が1か所)。以前は「画像の外周につながっている背景」だけを抜いていたため、**腕・剣・頭に囲まれた背景が島として残った**(実機で発生・2026-08-11)。緑や白のようなはっきりした背景色では、囲まれていようと背景は背景。
- **外周つながりを見るのは`black`(本体に黒がある)だけ。** ここが唯一の分かれ道なので、2か所目を作らない。
- 縁は0/255の二値にせず`SEG_SOFT`倍までを半透明にする。**ただし、やわらかくするのは背景に接している帯(`dilate2(bg)`)だけ。** 全面にかけると`black`で「囲まれているから被写体」と決めた黒い所まで透ける。
- **`despillInPlace()`が縁に残った背景色を抜く**(背景でいちばん強い成分を他の2成分の最大値まで下げる)。**残さない** —— 15%でも残すと緑の線が見える。`segment()`は**`img.data`の色も書き換える**ので、呼び出し側は必ず`img`と戻り値の`alpha`を一緒に使う。
- 背景の中の極小の粒(`SEG_SPECK`未満)は圧縮ノイズとみなして背景から外す。**本当の隙間は残す。**

- **背景の抜き方は歩行と静止画で別々**(`walkSeg()` / `#pmode`)。静止画の既定は`model`(下記)、歩行の既定は据え置き。「色で抜く」の色は下絵をタップして拾い`state.chroma`(歩行)/`state.chromaP`(静止画)に持つ。**色を拾っていないまま抜くと黒背景として処理されてしまうので`assertChroma()`で止める。**

### 学習済みモデルで抜く(`segmentModel()`・2026-09-02)

- **モデル = RMBG-1.4(量子化・約44MB)+ onnxruntime-web 1.19.2(WASM 単スレッド)。** GitHub Pages は COOP/COEP を付けられないので多スレッドは使えない。取得元は`MODEL_SRC`の**1か所**。「モデルで抜く」を初めて使ったときだけ取りに行き、Cache API に保存(2回目からは端末内)。無通信30秒で中断、ライブラリ読み込みは20秒上限。
- **`MODEL_CACHE`の名前は`sw.js`の`STUDIO_MODEL_CACHE`と二重に持つ。** スタジオも本番と同じオリジンなので、SWの`activate`が「知らないキャッシュ」として消してしまい、**ゲームを更新するたびに44MBを取り直していた**。片方を変えたら必ず両方直す。
- **欠けた物を保存しない。** 届いた量が`content-length`**より少ない**(=途中で切れた)/ **期待の実寸と数%以上ずれる**ときは投げて**キャッシュしない**。保存物も読み出すときに同じ物差しで見て、違えば捨てる。**期待の実寸は`MODEL_SRC.onnxBytes`に取得先と並べて持つ**(下限だけだと42.3MBのモデルに20MBが通ってしまう)。**多い(`got > total`)は異常ではない** —— gzipで返るCDNでは`content-length`が圧縮後の大きさなので、`!==`で見ると毎回弾かれる。`InferenceSession.create`に失敗したらそのキャッシュ項目を消す(**1度だけ**取り直しの機会を与え、2度目に「この端末では動かない」と決める=`MODEL_CREATE_TRIES`)。**1回目の文面で端末のせいにしない**(1回目=「もう一度お試しください」/ 2回目=「この端末では動かせません」)。
- **`modelState.err`(=もう試さない)にするのは「端末で動かない」ときだけ**(入口は`latchModelDevice()`1か所)。取得の失敗(圏外・CDN・途中で切れた)は毎回やり直せる。**`releaseSegmentModel()`はこの記憶を消さない** —— 技のプレビューを開くたびに通る道なので、消すと開くたび44MBを取っては捨てる。白紙に戻すのは人が「モデルをもう一度試す」を押したとき(`resetModelDevice()`)だけ(**`releaseSegmentModel`はasync。`release()`を await する。WASMヒープはこれでもOSへは返らない**)。
- **入口は`resolveAlpha(img, seg, prog)`の1か所。** `segment()`を直接呼んでいた3か所(`imageAlphaFor` / `buildWalkFrames` / `makePortrait`)はすべてここを通る。**「すでに半透明の画素がある絵はその透過をそのまま使う」判定もここが持つ**(これが無いと、透過済みPNGに既定の「モデルで抜く」が当たって44MBを取りに行き、圏外だと黒背景で抜き直してしまう)。**素通しするのは抜き方を明示していないときだけ** —— `model`と「自動」(`imageAlphaFor`が`auto`の印を付ける)がそれで、`white`/`chroma`/`black`/`blackopen`を人が選んだのなら透過済みでも必ず抜く(素通しにしていた頃は選んだ抜き方が黙って捨てられ、全面前景で返っていた)。判定は**1画素でも透けていたら**ではなく**割合**(`ALPHA_KEEP_RATIO`)で見る。モデルで抜けなかったら**必ず`blackopen`へ落として理由と次の手を`log`に出す**(処理を止めない)。**例外を日本語へ丸めるのは`modelErrorText()`の1か所。**
- **例外の理由は静止画・歩行の両方でその場に出す**(`#portraitMeta`/`#walkMeta`)。log だけに出すと「整えています…」のまま止まったように見える。
- **「中断」だけは`blackopen`へ落とさない**(黒背景で16コマ作り直しても意味がない)。`modelState.abort`(AbortController)を`segmentModel`の入口で見る。取得中の44MBも一緒に止まる。
- **`.modelNote`は呼び出し元のパネルだけ書き換える**(`modelNote(text, 'walk'|'portrait')`)。歩行の結果で静止画の説明を消さない。**例外の文面を出すので`innerHTML`は使わない。**
- 後処理の順は `dropSpecks(bg)` → 反転 → `keepMajor(8%)` → `tightenEdge`。逆順だと keepMajor が落とした粒を dropSpecks が拾い直す。**`keepMajor`(最大成分の8%以上は残す)はモデル経路だけ**。JS経路の`keepLargest`は不変。縁の締めの式は`tightenEdge()`に1つだけ置き、`segment()`からも`segmentModel()`からも呼ぶ。
- **入力は 1024×1024 固定**(量子化版の制約。512 を入れると onnxruntime が撥ねる)。「512で試して粗ければ1024」はできない。抜き終わりに「取得○秒 / 推論○秒 / 縁のやわらかさ○%」を`.modelNote`へ出す(次にモデルを替えるときの判断材料)。
- 動画の16コマは`segmentModel`を1コマずつ呼ぶ(1コマ約13秒/このサーバー。iPhone は数倍速い見込み)。**歩行側には所要時間の断りと「中断」ボタンを出す。** 1024²のcanvas4枚は終わりに`width=height=0`で捨てる(16コマぶん積み上がる)。技プレビューを開く前は`await releaseSegmentModel()`で解放する。
- 検査: `node tools/studio_regress.mjs --only model`(呼び分けの一致・**縁が半透明の1枚で明示指定が素通しに負けないこと**・keepMajor・`sw.js`とのキャッシュ名の一致)/ `node tools/studio_model_test.mjs`(ヘッドレスで IoU・キャッシュ・落ち方・途中で切れた応答・gzipのCDN・再試行・素通し・中断・用意できないときの言い方)。

### 技パネルと「撃ってみる」(本物の描画でのプレビュー・2026-09-02)

- **既定値を持つのはテンプレート(`MOVE_T1`/`MOVE_T2`/`TIER3`)だけ。** 入力欄は空 = 「テンプレートのまま」で、

- **弾か範囲かの判定は `moveKindNow()` 1か所。** 効かない欄を隠すのも(`applyMoveKindVisibility`)、
  値を集めないのも(`moveFieldHidden` → `collectMoveEdits`)ここを通る。
  根拠は combat.js の `fireMove`: `aoeShape` を持つ技は範囲の枝へ行くので `blast`/`projVisR`/`hitR`/`projStyle`/

    欄からも `collectMoveEdits` からも消えた)。順番は ①読み込んだ技の `aoeShape` の有無 →

  (`ZONE_PHASES[0].holdTime`)で安置が縮み始め、アイテムが湧き、やがて自機が死ぬ(実測: 175秒でHP0)。
  コマ撮り(`mode:'shot'`)は数秒しか回さないので従来どおり触らない。

### 登録済みの表を1項目だけ書き換える(走査器・2026-09-02)

- **`scanValue(text,i)`** = `{}` `[]` `''` `""` の対応を数えて値の終わりを返す純関数。**`pickEntry(text, table, key)`** = 表の開始〜`// <<AUTO:表名>>`に範囲を限り、`entryAnchors()`の錨を**当てる順に**試す。**`replaceField` / `replaceMoveField` / `replaceEntryValue` / `renameEntryKey`** = そのオブジェクトの**直下の**1項目だけ置換(無ければ末尾へ追加。末尾カンマの流儀は周囲に合わせる)。**置換はすべてこれを通す。技オブジェクトを再生成しない**(`jsMove`は新規登録専用)。
- **錨は2段。** ①行頭の`  key:`(ほとんどの表) ②`,`か`{`の直後の`key:`。②が要るのは**1行に複数項目を書く表**(`MONSTER_AURA`の`mocchi:'red', suezo:'yellow',` / `MOVE_AURA`の`'ファイア':'red','ファイアブレス':'red',`)。**必ず①を先に当てる**(②は「値の中のたまたま同じ名前」を掴む余地があるぶん弱い錨なので、①で取れる表の挙動を変えないため)。**②はさらに「表の直下(深さ1)」で絞る** — `entryDepthAt(text, open, keyStart)`が括弧の対応を数え、コメント/文字列の中なら-1を返す。絞らないと`blast:{ dmg:26 }`の`dmg`を表の項目として掴む(ジョーカー・アムピトリテに実在する形)。**①には深さの検査を足さない**(既に強い錨で、絞ると今まで取れていた表の挙動が変わる)。キーは裸でも引用符付きでもよく、`keyStart`/`keyEnd`で見出しの位置も返る(技名を変えたとき`MOVE_AURA`の見出しを書き換えるのに使う)。回帰は`MONSTER_AURA` 21/21・`MOVE_AURA` 63/63 を**エラーとして**検査し、入れ子の同名キーを掴まないことも見る。
