# 技エフェクトの採点表(批評家サブエージェント用)

## この文書の立場 — 先に読むこと

発注者の依頼は「最新の『原神』と同等以上の技エフェクト」。しかし**この開発環境に原神は無い**。
ビルドも映像素材も無く、外部から取得もしない。だから:

- **「原神の実物と並べて見た」と書いてはいけない。** 見ていないものを見たと書くのは嘘になる。
- 判定の根拠は**この採点表**と、**`tools/fx_shot.mjs` が出した実レンダリング画像**だけ。
- 到達点の言い方は「採点表の各項目で何点を満たしたか」。
  「原神を超えた」と断定しない。**満点でも「採点表を満たした」までしか言えない。**

採点表そのものは、原神・崩壊3rd・鳴潮など現代のアクションRPGのVFXに共通する
**作りの語彙**を項目に落としたもの。ここを満たせば「同じ土俵の作り」にはなる。

## 採点の手順(必ずこの順で)

1. `tools/fx_shot.mjs --sheet` が出した**連番シート**を見る。静止画1枚で採点しない。
   立ち上がり(0.05s)・伸び(0.18s)・着弾(0.38s)・余韻(0.7s)の4コマが揃って初めて時間設計を判定できる。
2. **改修前(base)と改修後(new)を必ず並べる。** 良くなったかは相対でしか言えない。
3. 下の10項目を各0〜5点で採点する。**根拠を必ず画像の中の具体で書く**
   (「派手さが足りない」は不可。「0.38sのコマで芯が白飛びしておらず、
   属性色のまま=光っているように見えない」のように書く)。
4. **1項目でも2点以下があれば不合格。** 合計点が高くても不合格。弱い所が画を決めるため。
5. 不合格なら**直し方を具体的に1〜3個**書く。「もっと良く」は指示ではない。

## 10項目

### 1. シルエット(0-5)
遠目・小さい画面でも**何の技か一目で分かる形**か。輪郭が読めるか。
- 5 = 縮小しても形が壊れない。他の技と取り違えない
- 3 = 大きければ分かるが、12px相当まで縮めると団子
- 0 = もやの塊。形が無い

### 2. 加算3層(0-5)
**白熱の芯 → 属性色 → 暗い煙/縁**の3層が重なっているか。
平らな単色は必ず安っぽく見える。**芯は必ず白飛びさせる**(255付近まで)。
- 5 = 芯が白・中間に属性色・外縁に暗い煙。境界が滑らか
- 3 = 2層まで。煙が無く、光が空中に浮いた板に見える
- 0 = 単色べた塗り

### 3. 軌跡(リボン/トレイル)(0-5)
動く物が**残像の帯**を引いているか。帯は先細りし、UVが流れているか。
- 5 = 太→細のリボン、内側に流れる筋、末端が溶けて消える
- 3 = 点の連なりだけ(粒が並んでいるのが見える)
- 0 = 何も残らない

### 4. サブエミッタ4段(0-5)
**発生 → 飛翔中 → 着弾 → 残り火**の4つが別々に用意されているか。
着弾だけ、発生だけ、は必ず物足りなく見える。
- 5 = 4段すべてあり、それぞれ形も寿命も違う
- 3 = 2段
- 0 = 1段(出て消えるだけ)

### 5. 地面デカール(0-5)
地面に**接地の痕**があるか。魔法陣・焦げ・広がる衝撃波の輪。
**カメラの扁平率に合っていること**(真円で描くと浮く。この作品の地面円の扁平率は約0.165)。
- 5 = 発生時の陣・着弾の焦げ・広がる輪の3つが地面に貼り付いて見える
- 3 = 輪が1つ。または扁平率が合わず浮いている
- 0 = 地面に何も残らない

### 6. 歪み・屈折(0-5)
熱・衝撃で背景が**歪む**か。炎の上の陽炎、爆風の球面歪み。
- 5 = 属性に応じた歪み(炎=上へ揺れる陽炎 / 爆発=球面の波)
- 3 = 歪みは無いが、代わりの明滅で衝撃は伝わる
- 0 = 何も無い

### 7. 時間設計(0-5)
**速く立ち上がり、ゆっくり減衰する。** 現代のVFXはほぼ例外なくこの形。
- 5 = 0.05sで既に最大に近い/0.7sでまだ余韻が残る/溜め(anticipation)が1コマある
- 3 = 立ち上がりが遅い(0.18sでようやく最大)か、余韻が無く0.4sで消える
- 0 = 出っぱなし、または一瞬で消える

### 8. カメラ・画面演出(0-5)
当たった感触が**画面側**にも出るか。揺れ・フラッシュ・放射ブラー・色収差。
- 5 = tier3の着弾で短い揺れ+周辺減光。効き過ぎず酔わない
- 3 = フラッシュのみ
- 0 = 画面は無反応
- **注**: 揺れは0.12s以下・振幅は画面高の1%以下。長い揺れは酔うので減点。

### 9. 色の作り(0-5)
属性色から**自動で**作られているか(決め打ちは減点)。彩度の高い部分と白飛びの分離。
スキンの色替え(`auraTint`)で青い炎・黒い炎になっても破綻しないか。
- 5 = 色は1つの元色から生成。色替えでも3層の関係が保たれる
- 3 = 色替えで芯まで染まり、白熱が消える
- 0 = 色が決め打ち

### 10. 二次運動(0-5)
主役の周りに**従属して動くもの**があるか。渦を巻く火の粉、乱流に流される灰、
上昇する熱気、地面を這う余波。**まっすぐ飛ぶだけの粒は二次運動ではない**。
- 5 = 乱流(curl)で曲がる粒、上昇気流、重力で落ちる欠片が同居
- 3 = 直線的に散る粒のみ
- 0 = 粒が無い

## 減点のかかる「やってはいけない」

この作品の決まりに反するものは、見た目が良くても**不合格**にする。

| 禁止 | 理由 |
|---|---|
| 画面上で楕円・矩形を決め打ち | カメラと合わず浮く。点は必ず`project()`で1つずつ投影する |
| 色の決め打ち | SSRスキンの色替え(`auraTint`)で破綻する |
| 通常マップで技が消える | Three.js層はリアルマップにしか無い。2Dの芯は必ず残す |
| 技の性能値(range/dmg/hitR)を見た目のために変える | 見た目と当たり判定がズレる |
| 負荷を理由にエフェクトを簡略化 | 発注者方針。「同じ見た目のまま安くする」方向で詰める |
| 60fpsを大きく割る | iPhone実機で遊べなくなる。`--bench`の数字を必ず添える |

## 報告の形

```
判定: 合格 / 不合格
点数: 1.シルエット 4 / 2.加算3層 5 / ... / 10.二次運動 3   合計 xx/50

    帯になっていないので速度が読めない。
直し方:
  1. ...
  2. ...
```
