# マルチプレイ(PvP)刷新 — 作業メモ(2026-08-14)

## 発注内容(そのまま転記・実装時に見返す)

> マルチプレイ(PvP)を刷新し、最新の『荒野行動』シリーズと同等レベルのゲーム性を構築してほしい
> (現状ではホストとゲストでプレイ環境に大きな差があり、ホストが圧倒的に有利)。
> 現状のゲーム性より良くなるならば、この作業に限り大規模なリファクタリングになっても構わない。
> 将来的に3人1組の20チーム戦が実装できるように、拡張性のあるPvPを実現してください。
> 思いつく限りのあらゆる要素に至るまで、すべてが荒野行動より高いクオリティで完璧かつ視覚的に美しいものにすること。
> サブエージェントを展開(ファンアウト)し、各項目を個別に担当させて完全に完璧な状態に仕上げる。
> 各項目に「/loop」を実行し、非常に厳しい批評家サブエージェントに視覚的チェックさせ、
> 荒野行動よりも良いと言えるまでループを継続。ブラインド比較。完全に完璧になるまで。

## 現状の診断(2026-08-14調査)

network.js(1307行)は既に: 入力seq+ack突き合わせ・スナップショット補間(ホスト時刻軸)・
ラグ補正(viewSeq巻き戻し)・差分/フル配信(20Hz)・ダッシュ/カード回数同期 まで実装済み。
**残る格差の根源は3つ:**

1. **Firebase RTDB経由の往復遅延そのもの**(片道50〜200ms)。ゲストの発射がホストに届いて
   実弾になるまで・被弾がauthStateで返るまでの遅延は、netcodeでは隠せてもゼロにできない。
   ホストは常に0ms。→ **WebRTC DataChannelでP2P直結**(RTDBはシグナリングとフォールバック)。
2. **ゲストの戦闘フィードバックが確定待ち**(与ダメ数字・ヒット感・キル表示)。
   → ローカル予測表示+ホスト確定で照合へ。
3. **チーム概念が無い**(entities/勝敗/スポーン/UIすべて個人戦前提)。

## アーキテクチャ決定

- **ホスト権威は維持する。** P2Pフルメッシュのロールバックは規模的に不可。
  変えるのは「配管」(トランスポート)と「体感」(予測表示)とチームの土台。
- **トランスポート抽象化**: `net_transport.js`(新規)。チャンネル= input / fire / auth / event /
  shot / loot / hit。バックエンドは `rtdb`(現行) と `rtc`(WebRTC DataChannel、
  シグナリングは rooms/{id}/rtc 経由)。**接続確立でrtcへ昇格、切断で自動フォールバック**。
  network.js の `window.__aramonSend*` / `__aramonWatch*` 呼び出しは透過的に差し替わる。
- **RTDBの新パス `rooms/{id}/rtc`** → セキュリティルールJSONを発注者へ渡す(貼るまではRTDBフォールバックで従来通り動く)。
- **rtc時は送信レートを上げる**: input 22→40Hz / auth 20→30Hz。補間遅延は実測ジッタに応じて
  120ms→適応(下限50ms)。RTDB時は現行レート維持(quota)。
- **チームの土台**: `ent.teamId`(null=個人戦)。部屋metaに `teamSize`。勝敗=チーム全滅、
  順位=チーム単位。スポーンは同チーム隣接。フレンドリーファイア無し。
  **ダウン→蘇生**(チーム戦のみ): HP0→ダウン(這い移動・出血タイマー)、味方が近接長押しで蘇生。
  全員ダウン/死亡でチーム全滅。botもチーム行動(集合・蘇生)。
- **人数**: まず 2人1組/3人1組 × チーム数で30体(現行と同じ規模)。60体(3×20)は
  データ構造上は制限なし・実機性能を見て解放(定員タブに追加するだけで動く形にする)。

## 検証ハーネス(批評家の測定器)

`tools/net_probe.html` + `tools/net_sim.mjs`(新規):
- ホスト+ゲストを**同一プロセスの2つの世界**として動かし、ローカル・トランスポートに
  人工遅延/ジッタ/欠落を注入(50/150/300ms RTT)。
- 測るもの: ①ゲスト自機の補正量(引き戻し) ②発射→実弾生成の遅延 ③被弾→表示の遅延
  ④遠隔エンティティのフレーム間ジャンプ(滑らかさ) ⑤ホスト/ゲストのキル成立率の対称性。
- **改修前にベースラインを取る**(改善を数字で証明する)。

## 既知の制約・注意

- サブエージェントは批評家サブエージェントを自分では起動できない(前回の実測)。
  **批評は統括(自分)が統合時に必ず実施する。**
- ソロ用とシード付き生成関数は対(spawnLoot/seededSpawnLoot等)。チームスポーンも両方作る。
- 新DBパスのルールJSONを発注者へ渡す(rtcシグナリング)。
- iPhone実機のWebRTC: Safari対応済みだが、必ずRTDBフォールバックを残す(遊べなくならない)。
- モードをまたぐ状態は入口で必ず消す(raidResetStateと同様、teamResetStateを作る)。
