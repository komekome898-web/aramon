## 制約(調べて分かった事実)

- **荒野行動の実物スクショは取得できない。** この環境の外向き通信はパッケージ
  レジストリ等に限定されており、画像ホストへのCONNECTは403で拒否される
  (確認済み: `upload.wikimedia.org` 403)。よって「実ゲーム画像との
  ブラインドA/B」は物理的に不可能。
  → 代わりに **(a) 版どうしのブラインドA/B(どちらが高予算のモバイルBRに見えるか)**
    と **(b) 荒野行動基準のルーブリック採点** で品質を追い込む。
    この点は発注者へ明示済み。
- **実機はiPhoneのブラウザ(PWA)。** 画質は「フレーム予算内で最大」。
  荒野行動自体がスマホで60fps級なので、重くて動かない画は「荒野行動超え」にならない。
- 遊びの動作確認は実機で発注者が行う。こちらは構文チェックとヘッドレス撮影まで。

## 手順(この順で進める)

1. ✅ 撮影ハーネス `tools/real3d_shot.mjs` + `tools/real3d_probe.html`
   - data.js/world.js をそのまま読み、試合開始と同じ手順でワールドを生成して撮る
   - シード固定なので、いつ撮っても同じ配置。`--bench` でfps計測
2. ✅ `real3d.js` をモジュール分割(サブエージェントが衝突せず並行作業できるように)
   - `real3d_common.js` ノイズ・テクスチャ生成の共通部品・テーマの箱(R3)
   - `real3d_sky.js` 空・遠景の山・環境光 / `real3d_terrain.js` 地面
   - `real3d_water.js` 水と溶岩 / `real3d_props.js` 山と障害物
   - **分割の正しさは「分割前後のスクショが一致すること」で確認する**
3. サブエージェントをファンアウト(担当ファイルを1つずつ持たせる)
4. クリティックがブラインド採点 → 合格するまでループ
5. 性能計測 → 構文チェック → PR → main → デプロイ確認

## 触ってはいけない約束(壊すと実機で事故る)

- 2Dの `project()` と3Dカメラの一致(FOV_V=64° / camPos / yaw,pitch)
- 地形の高さは `data.js` の `real3dHeightAt()`。当たり判定と同じ関数を使う
- 障害物の寸法は `data.js` の `OBST_SHAPES` が正。3Dモデルを変えたら表も直す
  (render.js の2Dくり抜きが同じ表を読む)
- `window.__aramonReal3D` の API 形(setActive/render/resize/stats/obstacleCullDist)
- 最大傾斜は0.3程度まで(超えると坂を登れなくなる。`CLIMB_TOLERANCE`)
