# PvP刷新の合格基準(批評家の物差し・2026-08-14)

実際の荒野行動へこの環境から接続はできないため、「荒野行動と同等以上」を
モバイルシューターの実測水準へ翻訳して数値化する。批評はこの表と、
ハーネス(tools/net_sim.mjs)の改修前後の数字の比較で行う。**全項目クリアまでループ。**

## A. ネットコード(片道75ms・ジッタ±30%条件で計測)

| # | 指標 | ベースライン(改修前に計測) | 合格ライン |
|---|---|---|---|
| A1 | ゲスト発射→ホスト実弾生成の遅延 | 計測待ち | rtc接続時 ≤90ms(平均)。RTDB比50%減 |
| A2 | 通常移動中の引き戻し(進行と逆向き補正) | 計測待ち | 0回/分(ダッシュ直後の猶予内を除く) |
| A3 | 被弾→ゲスト画面反映の遅延 | 計測待ち | rtc時 ≤110ms(平均) |
| A4 | 遠隔エンティティのフレーム間ジャンプ(p95) | 計測待ち | 理論移動量の1.6倍以内・スナップ0回 |
| A5 | キル成立の対称性(ホスト側vs.ゲスト側の所要差) | 計測待ち | 差 ≤120ms |
| A6 | rtc不成立時のフォールバック | — | RTDB経路が現行と同一(挙動差ゼロ)・切替でエラー0 |

## B. チーム戦

| # | 指標 | 合格ライン |
|---|---|---|
| B1 | チーム割当の決定性 | ホスト/ゲストで全60体が同一チーム(シード同一で毎回同一) |
| B2 | フレンドリーファイア | 同チームへの与ダメ0(直撃・範囲・状態異常・ノックバック全て) |
| B3 | ダウン→蘇生 | ダウン発生・bot/人間の蘇生・出血死・全滅判定が全て機能 |
| B4 | 個人戦の不変性 | teamSize=1で現行と挙動同一(既存テスト・目視) |
| B5 | 60体(3×20)の負荷 | ホストupdate ≤8ms/フレーム(iPhone実機は発注者確認) |
| B6 | 勝敗と順位 | チーム全滅で決着・placementがチーム単位で整合 |

## C. 視覚・体感(スクリーンショット批評)

| # | 指標 | 合格ライン |
|---|---|---|
| C1 | 小隊HUD | 味方のHP/ダウン状態が一目で分かる。既存HUDと調和 |
| C2 | 頭上マーカー・ミニマップ | 敵味方の識別が0.5秒以内にできる配色(色覚多様性も考慮) |
| C3 | ダウン表現 | ダウン中と死亡が明確に区別できる |
| C4 | ヒットフィードバック | ゲストでも発射・命中・被弾の応答が「即時」に感じる(数字+視覚) |
| C5 | キルフィード/リザルト | チーム戦の文脈(小隊全滅・蘇生)が伝わる |

## 批評の手順(統括が統合時に実施)

1. net_sim.mjs をベースライン→改修後で同条件実行し、A表を埋める。
2. team_test.mjs でB表を埋める。
3. ヘッドレスでスクリーンショット(チームHUD・ダウン・蘇生・リザルト)を撮り、
   別途起動する批評家エージェントにC表で辛口採点させる(「荒野行動より劣る点を最低3つ挙げよ」形式)。
4. 不合格項目は担当へ差し戻すか統括が直し、再計測。**全項目クリアまで繰り返す。**

## 60体の負荷が出た場合の逃がし方(先に決めておく)

- bot AIの思考間引き(遠距離botは0.2秒に1回)/ authStateのエンティティを距離で間引かない
  (ゲストの正が壊れる)代わりに、コールドフィールドの頻度を下げる。
- それでも重ければ「20チームはリアルマップ以外のみ」等の制限を発注者に提案(勝手に決めない)。
