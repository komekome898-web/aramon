# モンスター追加ツール(開発用)

ゲーム本体からは読み込まれません。すべて `tools/` の中で完結します。

## 何が自動になるか

1体追加するのに必要だった作業のうち、次が自動になります。

- 動画 → 歩行8コマ×2(正面/後ろ)の透過PNG。**動画が無くても画像から作れます**(iPhone版)
- **既存モンスターのSSRスキンの登録**(iPhone版)
- **SSRスキン専用の演出・BGM・SE・ガチャのピックアップ設定**(iPhone版)
- 静止画 → `monsters/<key>.png` / `<key>_player.png`(正方形・被写体が高さの9割・足元が下端付近)
- 色スキンの `hue` を静止画から自動サンプリング
- **9つの表への登録**(`ELEMENTS` / `TRAIT_DESC` / `SIGNATURE_MOVES` / `MOVE_AURA` / `MONSTER_AURA` / `SKIN_CONFIG` / `STATE_CHANGES` / `APTITUDE` / `WALK_ANIM`)
- 技3つの組み立て(tier1/2 は絵文字を選ぶだけ、tier3 は形のテンプレートを選ぶだけ)
- **検証**(登録漏れ・画像の不足・歩行コマの異常・JSの構文)

## 準備

```
pip install pillow numpy opencv-python-headless scipy imageio-ffmpeg
```

登録と検証だけなら上記は不要です(標準ライブラリだけで動きます)。

素材は `assets/<key>/` に置きます(gitには入りません)。

```
assets/mymon/front.mp4   歩行(正面)
assets/mymon/back.mp4    歩行(後ろ)
assets/mymon/icon.png    静止画(透過済み)
```

## 使い方A: iPhoneだけで完結(おすすめ)

Safariで開くだけの1ページです。Mac も Python も要りません。

**https://komekome898-web.github.io/aramon/tools/studio_web.html**

動画のデコード・背景透過・8コマ生成・9表への登録・GitHubへのコミットまで、
すべて端末の中で動きます(送信先は `api.github.com` だけ)。
ホーム画面に追加しておくと、トークンが消えにくくなります。

### 準備: GitHubのトークンを作る(初回のみ / Safariだけで完結)

1. Safariで **github.com** を開いてログイン
2. 右上のアバター → **Settings** → 左メニュー最下部の **Developer settings**
3. **Personal access tokens → Fine-grained tokens** → **Generate new token**
4. 設定
   - Token name: `aramon-studio`(任意)
   - Expiration: 90日など(切れたら作り直す)
   - Repository access: **Only select repositories** → `komekome898-web/aramon`
   - Permissions → Repository permissions → **Contents** を **Read and write** へ
     (`Metadata: Read-only` は自動で付く。他は触らない)
5. **Generate token** → 出てきた `github_pat_...` を**その場でコピー**(再表示されません)
6. スタジオの「1 GitHub設定」の欄に貼って**保存** → 「接続テスト」が通ればOK

保存先はSafariの localStorage(このドメイン・この端末のみ)。
権限はこのリポジトリの Contents だけなので、漏れても影響は限定されます。不要になったら
GitHubの同じ画面から **Revoke** できます。長期間開かないとSafariが消すことがありますが、
そのときは貼り直すだけです。

### 手順(上から順に押すだけ)

1. **GitHub設定** — トークンを保存 → 接続テスト
2. **登録の種類** — 「新しいモンスター」「既存モンスターのSSRスキン」「SSRスキン専用(演出・BGM・SE・ガチャ)」
   「既存の素材を差し替える(歩行・静止画)」「覚醒スキンを作る」「登録済みを開いて直す」から選ぶ(下記)
3. **歩行モーション** — 素材(動画 / 画像)を選ぶ → 背景の抜き方としきい値を変えながら8コマを確認。
   問題のあるコマは赤枠で理由付きに出ます。**8コマの下でゲームと同じ速さのアニメーションが再生されます**
   (1コマ0.11秒・8コマで約0.9秒。止める / 1コマ進める もできます)
   - **動画から作る** — 正面/後ろの動画。1周期を見つけて**候補16コマ**を出すので、
     その中から**使う8コマをタップで選べます**(既定は1つおき。「前半8コマ」「後半8コマ」も1押しで)。
     片足しか上がらないときは「切り出す長さ」を**周期の2倍**にしてプレビューし直してください
   - **画像から作る(動画なし)** — **2枚以上**の絵を順にコマとして並べます
     (8コマに足りなければ繰り返し、多ければ等間隔に選ぶ)。後ろの画像を省くと正面の絵を使います。
     1枚しか無いときは、その絵をAIで動画にしてから「動画から作る」へ回してください
     (**1枚の絵をパーツに切り分けて動かす機能は2026-09-02に廃止しました**。
     ルールで作った動きは「板が少し縮む」ようにしか見えず、歩いているようにはならないため)

#### AIで作った歩行動画を受け入れる

- **動画を選ぶと「背景の抜き方」は自動で「色で抜く」になります**(動画の既定)。
  背景色も外周8点(四隅+辺の中央)の中央値から自動で決まるので、**タップは0回**です。
  抜き方を自分で選び直したあとは、動画に切り替えても上書きしません
- **足元の影を落とす**(既定ON)。AI動画は足元に落ち影が出ます。被写体のいちばん下の帯で
  「暗い・彩度が低い・横に長い・**枠の中が詰まっている**」かたまりだけを影とみなして落とします。
  最後の「詰まっている」が無いと、絵の下に引いてある**細い線画**を影と間違えます
  (ゲームに入っている静止画89枚で illumine・mocchi_ssr の画素を消していました)。
  いまは**ゲームに入っている静止画89枚で1画素も消えません**(回帰で確認)。
  影が焼き込まれている歩行コマ(illumine の歩行など)では、これまでどおり落ちます
- **切り出し方**は「自動 / 周期で切り出す / 動きが最大の窓から選ぶ」。自動は、
  歩行の周期が見つかれば周期のぶん、見つからなければ**動きがいちばん大きい2秒の窓**から選びます。
  **見るのは動画の先頭4秒だけ**です(「動きが最大の窓」もこの中から探します)。
  歩いている所が動画の後ろにあるときは、そこだけを切り出してから読み込ませてください
- **コマの揃え方**は「横中心+足元(既定) / 足元だけ」。既定は毎コマを横の中心へ寄せ直すので、
  **体が左右に揺れるだけの動画ではその揺れが消えます**。診断の「揃え直しで捨てた横のぶれ」が
  大きいときは「足元だけ」にしてください
- **ゆっくり動く動画も受け付けます。** 「動いているか」を隣り合うコマだけで見ていたため、
  AI動画が**通ったり弾かれたり**していました(隣接差が判定の境目をまたぐ)。今は
  「隣り合うコマ」と「時間をおいたコマ」の両方を見ます(止まっている動画は両方0なので今までどおり止まります)
- **診断**がプレビューのたびに出ます。周期の強さ(自己相関の山)と、
  **①候補16コマ(抜く前)②抜いた後 ③並べた後**の3段で「隣り合うコマの差」を出すので、
  どの段で動きが消えたのかが分かります。周期らしさが 0.35 未満のときは
  **「歩行の周期が見つかりません」とはっきり出ます**(黙って周期を採りません)
- **「周期らしさ」が高くても、歩いているとは限りません。** この数字は
  **その場で揺れているだけでも上がります**(実物のAI動画で 0.47)。画面も
  「見つかりました」とは言わず、**並べた後の隣り合うコマの差(最小・平均)と
  「8コマを目で確かめてください」を必ず添えます**。最後の拠り所は出来上がった8コマです
- **16コマをモデルで抜き直す** — JSで抜いた縁が汚いときだけ押します。同じ区間をもう一度再生して
  1コマずつモデルで抜き直します(1コマ十数秒。進捗と「中断」が出ます)。
  **プレビューしたときの設定(切り出し方・長さ・揃え方・影)をそのまま使います。**
  設定を変えたときは「プレビュー」を押し直してください
- **AIで歩く動画を作るときの文**を動画パネルに置いてあります(日本語+英語・コピーできます)。
  その場で足踏み・脚がはっきり見える・カメラ固定・単色背景(緑)・5秒に2歩以上・キャラは中央に全身。
  **歩きは動画の側でしか作れません。**ここが満たされていない動画は、どんな抜き方でも
  「揺れる8コマ」にしかなりません

4. **静止画** — 画像を選ぶ → 背景透過+正方形に整形。色スキンの色相も自動で入ります。
   抜き方は歩行とは**別に選べます**(既定は「自動」= 透過済みならそのまま / それ以外は歩行と同じ設定)
5. **仕様** — key・表示名・色・特性・オーラ・適性6項目(新規モンスターのみ)
   - **色**(明るい色 / 暗い色 / 差し色)は**色パレットから選べます**。入れる場所を選んでから色をタップします。
     「明るい色から暗い色を作る」で暗い色を自動で作れます
   - **状態変化**(試合中に条件を満たすと一定時間だけ強くなる)を付けられます。
     選択肢は**今いるモンスターに入っている設定**をそのまま並べているので、同じものを選ぶだけで済みます。
     「自分で決める」にすると、発動条件(HP・ガッツ・命中時・被弾時・撃破時)と
     効果(与ダメ/被ダメ/ガッツ回復/クールタイム/消費ガッツ/移動速度/吸収)を組み合わせられます
6. **技** — tier1/2 は絵文字を選ぶだけ、tier3 はテンプレートを選ぶだけ(新規モンスターのみ)
7. **登録して本番へ反映** — 差分を確認 → 1コミットで `main` へ送信。
   `sw.js` の `CACHE_NAME` も自動で上がります。数分後のPagesデプロイで本番に出ます。
   間違えたら「登録を取り消す」で元に戻せます

#### 画面の見え方(段階バー・前回の続き・残り時間・失敗の出方)

- **段階バー** — 画面のいちばん上に7つの段(接続 / 種類 / 歩行 / 静止画 / 仕様 / 技 / 送信)が
  貼り付いていて、**用意できた段には ✓**、**エラーの段は赤に「!」**が付きます。
  タップするとその段のパネルへ飛びます。今の「登録の種類」で使わない段は薄く表示されます
  (状態は各パネルが持っているものを読んでいるだけなので、二重に管理していません)
- **前回の続き** — 仕様・技・色・登録の種類・抜き方の設定は、触るたびにこの端末へ自動で控えます。
  次に開いたときに「前回の続きから始める / 捨てて新しく始める」を聞きます。
  **絵と動画は控えません**(容量)ので、続きから始めても素材は選び直しになります。
  GitHubのトークンはこれとは別に保存されているので、捨てても消えません。
  **「登録済みを開いて直す」の入力は控えません** — 開いていた相手をGitHubから読み直さない限り
  欄だけ戻しても嘘になるためです。問いに答えずに打ち始めたときは「前回の入力は使わずに
  新しく始めます」と出て、消える前の1世代だけ端末内に退避します
- **残り時間** — モデルの取得・推論・動画の再生・16コマの抜き・送信は「○/○ ・残り約○秒」を出します。
  **決め打ちの秒数ではなく、その端末で実際にかかった時間から出す**ので、機種が違っても当たります
  (まだ1件も終わっていないときは数字を出さず「しばらくお待ちください」と言います)
- **失敗の出方** — 「理由 + 次にやること」の形にそろえてあります(トークン切れ・権限不足・
  送りすぎ・通信断・動画が読めない・被写体が見つからない・送信先が先に進んでいた、など)。
  **英語の例外がそのまま出ることはありません** — 対応表に無い例外も、まず日本語で
  次にやることを言い、元の英語は手がかりとして括弧で添えるだけです

### SSRスキンとして登録する

既存モンスターの見た目替えを追加します。入れるのは **`SSR_SKINS` / `SSR_SKIN_AURA` /
(技名を入れたときだけ)`SSR_SKIN_TIER3` / `WALK_ANIM` の素体の中** の4か所で、
素体の技・特性・適性は変わりません。**SSRだけの特典は tier3の技名と威力**です。

- 画像名はスキンidから決まります(`mymon_ssr` → `mymon_ssr.png` / `mymon_player_ssr.png` /
  `mymon_ssr_walk_f1..8` `_b1..8`)
- 素体の一覧は接続時に `data.js` の `ELEMENTS` から読みます(ツール側に一覧を持ちません)
- **歩行コマは1素体に何体ぶんでも**持てます(`WALK_ANIM` の `ssr` は配列で、装備中の `skinId` で選ばれる)。
  用意しなかったときだけ静止画になります(ゲーム側が自動で切り替えます)
- 専用の演出・BGM・SEは、登録後に「**SSRスキン専用**」で足します(下記)
- SSRの登録はiPhone版だけの機能です(CLI・Mac版GUIは新規モンスターのみ)

### SSRスキン専用(演出・BGM・SE・ガチャ)

すでにいるSSRスキンに、音と映像とガチャの扱いを設定します。書き込み先は
`data.js` の **`SKIN_MEDIA` 1か所だけ**で、ゲーム側のコードには何も足しません。

- **スキンを選ぶと、今そのスキンに設定されているものがその場で再生・表示されます。**
  差し替えたい項目だけ添付すれば、触っていない項目は今のまま残ります
- **ガチャ専用ムービー(昇格演出)** — 動画を添付して「無音動画と音声に分ける」を押すと、
  **音の無い動画**と**音声**の2つを作ってどちらもプレビューできます(ゲームは動画を消音で流し、
  音声を別に鳴らす作りなので、この2つが要ります)
- **専用BGM**(残り6人以上 / 残り5人以下 / 残り2人)と
  **専用SE**(tier3技 / 被弾時 / キル時 / 勝利時) — それぞれ動画を添付して
  「動画から音声を取り出す」を押すと音声だけを取り出してプレビューします。
  **すでに音声ファイル(mp3・m4a等)がある場合はそのまま添付すれば、取り出しは行いません**
- 取り出しは**動画を1回実時間で再生しながら録り直す**ので、長い曲はその長さぶん待ちます
  (再生中も端末からは音が出ません)。うまくいかない端末では音声ファイルを直接添付してください
- **宣伝・ガチャ画面画像** — ガチャ画面の待機中と、ロビーの記念ポップアップに出ます
- **ガチャの種類**(スキン / レイド)と**ピックアップ**のスイッチ。
  「する」にすると、そのガチャのタイトルが「(◯◯ピックアップ)」に変わり、
  ガチャ画面とポップアップの画像もこのスキンのものになります
  (画像を添付していなければ、今そのスキンに設定されている画像が出ます)
- 「登録を取り消す」を押すと、**このスキンの専用メディア設定だけ**を消します(スキン自体は残ります)

### 既存の素材を差し替える(歩行・静止画)

**すでにいるモンスター・SSRスキンの絵だけを作り直して入れ替えます。**
登録行(仕様・技・特性)は何も触らないので、後から絵を描き直したときや、
登録時に素材を入れ忘れたときはこれを使います。

- 差し替え先は**素体(ELEMENTS)とSSRスキン(SSR_SKINS)が1つの一覧**に並びます。
  歩行コマがまだ無いSSRスキンには「**※歩行コマなし**」が付きます
- **用意したものだけを送ります。** 歩行だけ・静止画だけの差し替えもできます
  (歩行は正面・後ろの両方をプレビュー、静止画は「背景を抜いて整える」を押した時が「用意した」状態)
- 画像名は登録時とまったく同じ規則で決まるので、入れ先を間違えることはありません
- **歩行コマが未登録のSSRスキンは、画像の送信と同時に `WALK_ANIM` への登録も行います。**
  これが無いと画像を送っても静止画のままになります
  (メタルグレイモンで実際に起きました。当時は「1素体に1つ」の制限で歩行が黙って落とされていた)
- 差し替えのときは `UPDATE_HISTORY` に足しません(見た目の入れ替えなので対象外)
- 登録行を触らないので「登録を取り消す」ボタンは出ません

### 登録済みを開いて直す(仕様・技・色・SSR設定)

**すでに data.js にいるモンスター・SSRスキンを開いて、数字や技を直します。**
手書きで足した古い15体も開けます(目印の有無で処理を分けていません)。

1. 一覧から相手を選び **「この内容を読み込む」** — いまの `data.js` の中身が下の欄に入ります
   - モンスター → 仕様パネル(名前・色・HP・移動速度・特性の倍率・オーラ)+ 技パネル3段 + 色スキンの欄
   - SSRスキン → 表示名・オーラ・専用tier3の技名と威力倍率・シーズン限定・討伐報酬限定
2. 直したい欄だけを書き換える(**空欄は「触っていない」。空にしてもその項目は消えません**)
3. **「差分を確認する」** — 変わった項目の一覧と、評価して確かめた差分が出ます
4. **「この内容でコミット」**

守っていること:

- **正は常に `data.js`。** `monsters/specs/*.json` は見ません(ツールで作った6体ぶんしか無いため)
- **書き戻すのは触った項目だけ。** その項目の値の文字だけを差し替えるので、
  手書きのコメント・ツールが知らないキー・並び順はそのまま残ります(技オブジェクトは作り直しません)
- **技名を変えると `MOVE_AURA` の見出しも同時に直します**(直さないとその技のオーラが黙って消えます)
- **読み込んだ直後に「入れ直しただけで差分が出ないか」を自分で確かめます。**
  出たらその読み込みを**取り消します**(欄には入りますが「読み込んだ」ことにしません)
- **開いた技はそのまま「撃ってみる」で撃てます。** key の欄と技3段(形・数字・語彙)に
  いまの技の値が入るので、プレビューは**開いている技そのもの**を撃ちます。
  どのテンプレートにも当てはまらない技(手書きの技)は形が「テンプレート無し(いまの技のまま)」になります
  - **「形」の欄は、いまの技に近いテンプレートを当てはめて見せているだけです。**
    土台は**常に開いた技**なので、欄の無い設定(貫通・命中時の速度上昇・追加の爆風など)も
    そのまま撃てます。テンプレートの数字になるのは、**自分で形を選び直したときだけ**です
- **登録の種類を切り替えると、ここで入れた値は欄ごと元に戻ります**(新しいモンスターの登録に混ざらないように)。
  覚醒スキンの「継承の断り」のような**注記も一緒に消えます**
- **送信前に、書き戻した `data.js` を空の枠の中で本当に評価して**、
  意図した差分以外がゼロであること・**意図した差分がすべて出ていること**・
  **更新履歴が意図した1行しか変わっていないこと**を確かめます。どれか1つでも外れたら送りません
  (更新履歴は**1行ずつ本文とタグで**見るので、書き方の並びが違うだけでは止まりません)
- **送るファイルは全部、送る前に「読める形か」を確かめます**(`data.js` だけでなく `ui.js` / `sw.js` も)。
  どれか1つでも壊れていたら送りません
- **読み込んだときと送る直前で、書き戻すファイル全部(`data.js`、特性を足したときは `ui.js`、`sw.js`)の
  中身(blob の sha)を照合します。** その間に誰かが変えていたら中止して「読み直してください」と出します
- 更新履歴は**性能の数字を変えたときと技名を変えたとき**だけ1行(`ジョーカー: 威力21→34・連射5→7`)。
  今日のかたまりに**このツールが書いた形の、同じ相手の行**(`ジョーカー: …`)があれば**その行を書き直します**
  (2行あると古いほうが嘘になるため)。**別のモンスターの行と、告知の行(🆕・✨・✵)は書き直しません**
  —— 名前が同じというだけで「新モンスターが登場しました」を消してしまわないためです。
  自動で入るのは**最初に「差分を確認する」を押したときだけ**で、書き直す行はあとから選び直せます。
  タグは技名なら「モンスター」・数字なら「バランス」・両方なら両方。
  見た目(オーラ・エフェクト色・色スキン)だけの変更では入れません。本文を空にすれば入れないこともできます
- **特性idを変えたときは新規登録と同じ判定**をします。形は**英小文字で始まる英数字と `_`**
  (`bad-id` のような字は止まります。そのまま送ると `ui.js` が壊れて一覧が丸ごと出なくなります)。
  `ui.js` の `TRAIT_DESC` に無い特性idなら「特性の説明」が要り、書けば `ui.js` へ1行足します
  (すでにある特性idなら何も足しません —— 同じ特性を持つ既存モンスターの説明を書き換えないため)
  - 手書きで足した古い体に新しい特性を足すと、**`ui.js` の `TRAIT_DESC` の行にだけ `/*@key*/` の目印が付きます**
    (その体の `data.js` 側の行には付きません)。目印の有無で「ツールが登録した体か」を判断しないでください
- **覚醒スキン(元スキンの覚醒後)の tier3 は元スキンから継承する**ので、技名と威力倍率の欄は止まります
- 絵は触りません(絵の差し替えは「既存の素材を差し替える」)。素体・スキンidも変えられません
- 登録行を足さないので「登録を取り消す」ボタンは出ません

触れないもの(それぞれの登録画面が正): 命中時の効果(`TRAIT_ON_HIT`)/
状態変化(`STATE_CHANGES`)/ 育成適性(`APTITUDE`)/
レイド特効(`RAID_EFFECT_SKINS`)/ ガチャのピックアップ(定数)。

「色で抜く」を選んだときは、その場に出る下絵の**背景をタップ**して色を拾います(歩行・静止画で別々に持ちます)。

**抜けない素材だけMac版へ回してください。** 難しい背景(草・金屏風など)のGrabCutはMac版だけにあります。

## 仕組み(壊さないための約束)

- 表への挿入位置は各表の末尾にある `// <<AUTO:表名>>` の行です。**この行を消さないでください。**
- 追記した行には `/*@key*/` の目印が入ります。`--revert` はこの目印で行を特定して消します。
- 挿入は全表を1回のトランザクションで書きます(途中で失敗したら何も書きません)。
- 背景除去のアルゴリズムは既存の `tools/build_walk.py` をそのまま呼んでいます。
  モンスターごとに積み上げたモード(`white` / `black` / `blackopen` / `grass`)の資産はそのまま使えます。
- **iPhone版(`studio_web.html`)は同じ目印方式をJSへ1:1移植したもの**なので、どちらで作っても
  出来上がる行は同一です(`renderRows` の出力がPython版と一致することを確認済み)。
  移植していないのは `grass`(GrabCut)と256色量子化だけです。
- **歩行周期の検出(`detect_period` / `detectPeriod`)もPython版とiPhone版で同じ手順・同じ定数**です。
  同じ動画から同じ周期が出ることを確認しています。**片方を直したらもう片方も直してください。**

## `changelog_check.mjs`(更新履歴)

書き方のルールは CLAUDE.md の「更新履歴の書き方」にあります。ここはそれを機械で見られる分だけ見ます。

- **エラー**(直すまで通らない): 形の壊れ、`YYYY-MM-DD` でない日付、**同じ日付のブロックが2つ**、降順でない、`CHANGELOG_TAGS` に無いタグid、空の本文。
- **注意**(人が見て判断する): **最新の日付のブロック内**で似た話題の行、遊ぶ人に関係のない内部の言葉。
  過去の日付は公開済みで、似た語が並ぶのは自然(「歩行アニメーションを追加」等)なので見ません。直すべきなのは「今日の分に同じ話題の行を2つ作った」場合だけです。
- 似ているかどうかは**文字の並びではなく出てくる言葉**(漢字・カタカナの語)で見ます。日本語は言い回しを変えると文字の並びがまるごと変わるためです。

どちらも**マルチの組み立て(`beginMultiplayerMatchInner`)を直接呼ぶ。** 通信の入口(`window.__aramon*`)だけをその場のスタブへ差し替えるので、チーム割当・スポーン・bot生成は実際の試合とまったく同じ道を通る。

- **チーム戦の入口はマルチだけ**(2026-08-19に「チーム戦のソロ出撃」を廃止)。`startGame({teamSize,…})` でチーム戦を組むことはもうできない。`team_test.mjs` は入口が消えたあとも古い呼び方のままで落ちていたので、この形へ直した(2026-08-24)。
- **送信系のスタブを1つでも欠かすと試合の途中で落ちる**(`__aramonPushLootEvent` 等はアイテム取得のたびに呼ばれる)。増やしたときはスタブの一覧にも足すこと。
- `requestAnimationFrame` は空にする。テスト側が `update(1/60)` を刻むので、裏でループにも回されると同じフレームが二度進む。

## `undef_check.mjs`(未定義の識別子)

`node --check` は**構文しか見ない**ので、「関数を切り出したときに引数を渡し忘れた」型の事故を必ず素通しします。
2026-08-23に `firebase.js` の `createRoomInner` が `mapPick` を受け取っておらず、
**「部屋を作る」が必ず失敗**しました(ESモジュールは常に strict なので `ReferenceError`)。
それを止めるための検査です。

- classic script は互いにグローバルを共有するので、**全ファイルのトップレベル宣言と `window.X = …` を集めてから**照合します
  (`index.html` の中に直接書いてあるスクリプトも読みます)。
- `typeof X` は「あるかどうか調べる」正しい書き方なので対象外です。
- **宣言なしの代入は「グローバルを作った」と見なしません。** 認めると打ち間違いがそのまま通ってしまうためです。
- 外から差し込まれる名前(`__netProbe` 等)はファイル冒頭の `INJECTED` に**理由付きで**書いてあります。
- `acorn` が要ります。無ければ何もせず終わります(`ARAMON_TOOL_MODULES=<node_modulesの場所>` で場所を渡せます)。
- ファイル名を渡すと**そのファイルだけ**を調べます(検査そのものが効いているか確かめるのに使います)。

```
node tools/undef_check.mjs                 # リポジトリ全体
node tools/undef_check.mjs path/to/one.js  # 指定したファイルだけ
```

## `layout_test.mjs`

10端末 ×(5モード × 選択有無2 × 負荷3種 + 別画面8通り + 画面ごとの方針21通り)。4分ほどかかります。

**画面の3原則を機械で守るのがこのツールです**(CLAUDE.md「全画面に効く決まり」と同じもの)。

  R1 箱は画面から決める / R2 スクロールするのは「読む物」だけ(操作はスクロールの外) /
  R3 縦が足りないときに削る順番を画面ごとに決めておく

- 検査対象は `#startScreen`・`#lobbyScreen`・`#roomListScreen`・`#resultScreen` に加えて、
  **ファイル冒頭の `PANELS`(画面ごとの方針の表)に並べた全画面**。
  **画面を1つ足したら `PANELS` へ1行足すこと。** 足さない画面は検査されません。
- 端末には「**縦を20/35/55px削られた状態**」を含みます。iOSはPWAを横向きで起動した直後、
  まだ縦持ちのセーフエリアを返すことがあり、そのぶん低い画面でレイアウトが確定するためです。
- **字の大きさそのものは検査しません**(2026-08-26 発注者判断)。
  見るのは「その字が箱の中に収まって見えているか」(縦に切れる/横に切れる)まで。
  文字が小さいのは**レイアウトを守るために意図してそうしている**ことが多く、
  それを不具合として挙げると「直す」=字を大きくする=行が伸びる=画面が崩れる、と
  **この検査が防ぎたかったことを起こさせる**方向へ働きます。読みやすさは実機を見た人が決めます。
- いま直せない指摘は**ファイル冒頭の `KNOWN` に理由付きで登録**してあり、実行のたびに件数が出ます
  (「見なかったことにする」のではなく「意図的に許した」を残すため)。直したらその行を消します。
  **いまは空です**(= 見えている画面はすべて基準を満たしている)。
- `LOBBY_TEST_ALL=1` を付けると省略せず全件出ます。

## `hooks/`

Claude Codeが自動で回す検査。`.claude/settings.json` から呼ばれます(手で叩くものではありません)。
CLAUDE.mdの「絶対に守るルール」のうち、忘れると事故になる4つを機械で止めます。

| スクリプト | いつ動くか | 何を止めるか |
|---|---|---|
| `js_syntax.sh` | `.js`/`.mjs` を書き換えた直後 | `node --check` が落ちるコード |
| `changelog.sh` | `data.js` を書き換えた直後 | 更新履歴の形・日付・重複のエラー(注意は止めずに伝えるだけ) |
| `cache_bump.sh` | 作業を終えるとき | 配信するファイルを変えたのに `sw.js` の `CACHE_NAME` が据え置き(絶対ルール1) |
|  `layout.sh` | 作業を終えるとき | `style.css`/`index.html`/`ui.js` を触ったのに画面レイアウトの検査を通していない |

- 止めるときは終了コード2で、理由がそのままClaudeへ返ります。
-  `layout.sh` は3分かかるので、**同じ中身では二度回しません**(`.claude/hooks-cache/`にハッシュを控える。gitには入れない)。
  `playwright`が無い環境では黙って飛ばします。
- 一時的に全部止めたいときは `.claude/settings.json` の `hooks` を消すのではなく、
  Claude Codeの `/hooks` から個別に外してください。
